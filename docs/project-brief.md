# 项目申报书（一页）

## 项目名称

**moonstrong —— 力量训练智能编程引擎**

## 赛道

新项目赛道（MoonBit 2026 九月黑客松）

## 仓库

https://github.com/XiaoMao-MYY/moonstrong.mbt （public，默认分支 `main`，CI 已通过）

## 一句话定位

把"今天练多重、几组几次、该不该加重量、该不该减载"变成一组可调用、可测试、
可复现的 MoonBit 纯函数。

## 要解决的问题

力量训练的训练量决策目前依赖教练经验、Excel 或商业 App，工程上有四个硬伤：
计算逻辑与界面耦合无法复用和测试；公式选择随意，同一输入不同工具给出不同结果；
估算值被当确定值用，没有不确定性表达；多数方案依赖云端、离线不可用。

## 目标用户

1. **自己训练、愿意量化进阶的力量训练者** —— 需要一个可信、离线、不上传个人数据的计算器。
2. **健身教练 / 训练计划设计者** —— 需要把重复计算固化下来，把精力留给个体判断。
3. **健身类 App / 小工具的开发者** —— 需要一个零依赖、跨后端、可直接嵌入的计算内核，
   不必自己抄一遍容易抄错的公式。

## 功能边界

**做**：1RM 估算、RPE/RIR 处方、训练容量量化、身体成分与能量估算、周期化计划生成、自适应调整。

**不做**：医疗与康复建议、HRV / 伤病风险评估、个人数据采集与上传、UI 与设备连接。
这是刻意划定的边界——生态中已有侧重健康监测的项目，本项目只做训练处方计算。

## 独立价值与去重说明

- MoonBit 生态中**不存在**力量训练处方计算库（无 1RM / RPE / 周期化 / 训练营养类库）。
- 与生态中已有的健身类项目**方向不同**：那些侧重生理信号监测与风险评估，本项目侧重
  **训练处方的计算与生成**，二者不构成替代关系。
- 本项目不是任何既有项目的重命名或重新打包：代码从零编写，公式来源公开可查
  （见 `THIRD_PARTY.md`）。

## 技术亮点

1. **多公式加权共识而非单一公式**：按次数给 4 种 1RM 公式分配可信度权重后加权平均，
   抑制单一公式的系统偏差，并用 `estimate_confidence` 显式表达不确定性。
2. **零第三方依赖 + 只使用四则运算**：刻意回避 `log10` 等超越函数，保证跨后端
   （wasm / js / native）数值完全一致、结果可复现。
3. **带跌幅保护的自适应**：`next_training_max` 设置 10% 跌幅下限，
   避免一次状态不佳的 AMRAP 就让训练量断崖式下降。
4. **MoonBit 语言特性落地**：代数数据类型 + 穷尽模式匹配表达训练状态机；
   `raise InvalidInput` 做可判定的错误处理；白盒测试覆盖正常值 / 边界值 / 错误路径。
5. **踩坑并定位了工具链问题**：发现并验证了 MoonBit 当前版本中 `pub` 为只读可见性、
   跨包构造需 `pub(all)` 这一语义，已在库与文档中给出结论（详见 `docs/test-record.md` 4.2）。

## 已知局限（不隐瞒）

- 1RM 估算在高次数下误差放大，已用置信度下调提示。
- 体脂用 Deurenberg（基于 BMI），对高肌肉量人群系统性高估——这是为换取跨后端数值
  一致性所做的取舍，已在 README 中写明，并允许调用方直接传入实测体脂。
- 尚未在 Linux / macOS 的 CI 上跑过；尚未做属性测试与跨后端数值实测。
