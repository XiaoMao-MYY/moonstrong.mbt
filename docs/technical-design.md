# 技术设计

## 1. 问题定义

力量训练的核心决策——**今天练多重、几组几次、下次加不加、什么时候减载**——目前主要
依赖三种方式：教练经验、Excel 表格、商业 App。它们共同的工程问题是：

1. **计算逻辑与展示耦合**，无法被复用和测试；
2. **公式选择随意**，不同工具对同一组输入给出不同结果，且不说清差异来源；
3. **没有不确定性表达**，一个估算值被当作确定值使用；
4. **离线不可用**，多数方案依赖云端。

本项目的定位是：把上述决策中**可计算的部分**抽成一组纯函数，做到可测试、可复现、
零依赖、可嵌入。

## 2. 设计原则

| 原则 | 落地方式 |
| --- | --- |
| 纯函数优先 | 无全局状态、无 IO、无随机；相同输入恒定输出，跨后端（wasm / js / native）一致 |
| 零第三方依赖 | 只依赖 MoonBit 标准库的 `Debug`；不引入需要超越函数的库，保证跨后端确定性 |
| 显式不确定性 | `estimate_confidence` 随次数下降；多公式共识而非单一公式 |
| 单位与量纲统一 | 重量一律 kg，百分比一律 0..1；展示层负责换算 |
| 错误可判定 | 非法输入统一 `raise InvalidInput`，不做静默截断 |
| 边界说清楚 | 明确不做医疗建议、不做 HRV / 伤病评估 |

### 一处刻意的取舍：为什么不用超越函数

体脂估算没有采用 Navy（美国海军）围度法，而是 Deurenberg（基于 BMI）。原因：
Navy 法需要 `log10`，不同后端对超越函数的实现精度不一致，会破坏"跨后端结果一致"
这一承诺。Deurenberg 只用到四则运算，代价是对高肌肉量人群系统性高估体脂——
这个偏差在 README 与本文档中明确写出，而不是藏起来。

## 3. 模块划分

```
types.mbt    公开类型 + 单位换算（WeightUnit / Sex / Lift / Goal / InvalidInput）
onerm.mbt    1RM 估算：4 公式 + 加权共识 + 逆运算
rpe.mbt      RPE ↔ 百分比 ↔ RIR 互转，及"目标次数+余量 → 重量"
volume.mbt   容量负荷 / 有效次数 / INOL / 平均强度 / 密度
body.mbt     BMI / 体脂 / FFMI / BMR / TDEE / 宏量营养素
program.mbt  5/3/1、StrongLifts 5×5、DUP，以及取整到杠铃片
adapt.mbt    状态判定 / TM 推进 / 平台期检测 / 减载建议 / 容量调整
catalog.mbt  枚举取值目录（供 CLI、UI、文档生成使用）
```

模块间依赖是单向的：`types` ← `onerm` / `rpe` / `body` ← `volume` / `program` ← `adapt`。

## 4. 关键算法

### 4.1 多公式加权共识 1RM

单一公式各有系统偏差：Epley 在高次数偏乐观，Brzycki 在低次数偏保守。
本项目不"选一个最好的"，而是**按次数给每个公式分配可信度权重后加权平均**：

```
consensus(w, r) = Σ formula_weight(f, r) · estimate_1rm(f, w, r) / Σ formula_weight(f, r)
```

`formula_weight` 依据：低次数（≤5）各公式分歧小，都给高权重；中次数（6–10）
Epley / Brzycki 拟合较好；高次数（>10）误差普遍放大，O'Conner 衰减较慢故相对权重上升。

越界公式（Brzycki ≥37 次、Lander ≥38 次）由 `estimate_1rm_all` 自动剔除——
这不是容错，而是定义域本身的要求。

### 4.2 RPE / RIR 处方

RPE（自觉用力程度）与 RIR（剩余可完成次数）是同一件事的两种表述。
本库维护一张锚点表做插值，支持双向换算，并直接回答真实问法：

```
weight_at_rir(one_rm, target_reps, rir) → 应当使用的重量
```

### 4.3 自适应调整

- `performance_status`：比较当日 e1RM 与基线，输出 `Fresh / Normal / Fatigued / Overreached`。
- `next_training_max`：按 AMRAP 完成次数推进 TM，并**设置 10% 的跌幅保护下限**
  （`current_tm × 0.90`）。这是一处设计修正：初版直接用 `e1RM × 0.9` 作为新 TM，
  实测发现一次状态不佳的 AMRAP 就能让 TM 掉 12%，会导致训练量断崖式下降。
- `detect_plateau`：在滑动窗口内检测 e1RM 是否停滞。
- `suggest_deload`：结合连续训练周数、疲劳状态、平台期给出减载建议与系数。

## 5. 测试策略

58 条白盒测试（`*_wbtest.mbt`），每个公开函数覆盖三类路径：

1. **正常值**：与已知公开算例对照；
2. **边界值**：公式定义域边界（如 Brzycki 36/37 次）、0 与极小值、RPE 0/10；
3. **错误路径**：用 `try { } catch { }` 断言确实抛出 `InvalidInput` 的正确变体。

浮点比较统一走 `expect_near`，采用**四舍五入**而非截断到 2 位小数——
初版用截断，导致恰好落在 2 位小数边界上的值（如 0.005）出现假失败。

全部测试在 `--deny-warn` 下通过。

## 6. 已知技术债

- 体脂仅支持 Deurenberg；未来若要支持围度法，需先解决跨后端超越函数一致性问题。
- 周期化目前覆盖 5/3/1、5×5、DUP 三种，尚未支持块周期与共轭法。
- 营养模块尚未按体重变化做回测修正。
